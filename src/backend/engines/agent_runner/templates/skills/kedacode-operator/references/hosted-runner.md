# Hosted Runner

Read this reference before operating hosted maintenance, onboarding or credentials, or the optional Linux desktop. Hosted mode is opt-in and keeps each customer's repo credentials and runner state isolated.

## Host maintenance

`kc container gc` is a manual, host-wide operation and defaults to preview (`kc container gc --dry-run`). Dangling images and selected Buildx cache records may belong to any local project on that host, so inspect candidates before applying. Only after review should an operator run `kc container gc --apply`; `--cache-retention-days <days>` changes the default 90-day window. It never prunes volumes, bind mounts, or images referenced by containers. Runner Compose never mounts the host Docker socket, and ordinary local `kc daemon run` does not start this cleanup.

Hosted daemon maintenance stays off unless `hosted_maintenance_enabled = true`. It waits until all Issue workers finish, then runs the conservative worktree cleaner with `force=false`, removes completed run/attempt summaries older than 90 days, and prunes per-Issue raw output logs older than 14 days. It removes only closed, inactive Issues whose managed worktree is clean, merged, and has no remote branch; active, dirty, unmerged, remote-existing, and unreadable GitHub candidates are skipped. Audit, queue, settings, active state, and credentials are outside summary cleanup. The disk-watermark gate pauses new work below 10 GiB and resumes it above 15 GiB; it never kills an in-flight Issue. An unreadable disk probe fails closed and refuses new Issues.

## Console onboarding and credentials

When `[agent_runner.hosted].enabled = true`, the Console requires authenticated HTTPS and does not reuse the local no-op session. The VM operator creates the first-admin code with `kc console bootstrap-token create` (default `--expires-in 24h`; also `30m`, `2d`, or raw seconds). The code prints once, is stored server-side only as a SHA-256 digest, expires, and can be consumed once. Re-issuing invalidates the previous unused code. Invalid expiry exits `2`; the command exits `1` when hosted mode is disabled. Hand the code over out-of-band; the customer pastes it into the web bootstrap form to set the admin password. Public self-registration stays disabled.

The VM operator configures one `repository_id` and absolute `repository_path` under `[agent_runner.hosted]`. The checkout origin must match the validated PAT's `owner/repo`. Once both GitHub and Agent credentials are active, the customer may start that repo's runner from the protected Console. Hosted Compose mounts only the checkout, its repo-specific tmpfs native-auth directory, and a repo-named Docker volume for run history, audit, queue state, and raw logs. It does not mount the host-wide KedaCode state home, credentials vault, data key, or Console database. The auth root must be Linux `tmpfs`, and `kc container gc` does not prune the state volume.

The Console accepts one single-repo fine-grained GitHub PAT and a Claude, Codex, or Kimi provider API key. It never accepts OAuth/session data, auth-file uploads, GitHub Actions secrets, project DB credentials, SSH keys, or reverse-proxy TLS keys. Secrets are encrypted per repo and delivered only through that repo's tmpfs native-auth file; they never enter URLs, browser storage, SQLite, logs, Compose environment, `docker inspect` environment values, or argv. GitHub validation uses read-only requests with the token in a header. Saving a provider key does not call a model; connectivity testing requires explicit cost confirmation and makes one minimal request. Deleting a credential stops that repo's runner and clears the local ciphertext and tmpfs copy, but does not revoke the upstream credential. The customer must revoke it with the provider. Isolation is at the repo and single-tenant VM boundary; code inside a runner can read that runner's own delivered key.

## Optional Linux desktop

When `[agent_runner.hosted].desktop_enabled = true`, use `kc-computer status` to confirm the private X11 display, then `screenshot`, `click`, `type` (text comes from stdin), `key`, and `scroll` to operate a Linux GUI application inside the runner. This is provider-neutral shell tooling, not browser-only Playwright or a remote desktop service. For visual evidence, start `kc-computer record start --output <repo>/tasks/evidence/<prd-stem>/rv-<n>-desktop-operation.webm`, perform the real UI actions, and run `kc-computer record stop`; inspect the WebM and adjacent `.actions.jsonl` before publishing. The trace stores action metadata and input length, never typed text. Do not record by default or expose VNC/noVNC ports, and do not claim the video proves a flow it does not show.
