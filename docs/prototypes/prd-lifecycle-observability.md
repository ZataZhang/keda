# PRD 生命周期观测与执行分析原型

本页归档 `tasks/pending/P1-FEAT-20260921-161621-prd-lifecycle-observability.md` 的交互原型，用于在实施前确认三件事：Backlog 单 PRD「执行过程」的信息层级、端到端耗时的拆分口径怎么读、以及失败/阻塞/观测缺口如何在不覆盖历史的前提下呈现。这是一个 **interactive prototype**（静态 fixture 驱动），不代表生产功能已实现或已接入真实 API。

时间线部分已按 `tasks/pending/P1-FEAT-20261010-092630-lifecycle-invocation-detail-timeline.md`（Issue #273）的目标形态升级：事件按「执行会话 → Agent 尝试 → 调用」三层归组，尝试可展开调用明细，同秒重复行折叠，三类缺口分别披露。该形态的前端组件与读取契约已落地（`frontend-public/components/backlog/prd-lifecycle-timeline.tsx`、`GET …/backlog/prds/{encoded}/lifecycle` 的 `invocations` 区），本原型继续承担「改动前先确认形态」的作用；统计视图仍属概念演示。

## 打开方式

- 文档站入口：[Prototype Hub](hub.html)，从列表选择「PRD 生命周期观测与执行分析」
- 直接入口：[打开交互原型](prd-lifecycle-observability.html)
- 本地预览：`uv run mkdocs serve`，然后打开 `http://127.0.0.1:8000/prototypes/prd-lifecycle-observability.html`
- 左侧 Settings 入口打开[生命周期与执行器设置原型](lifecycle-agent-matrix.html?screen=settings)；返回该原型后，左侧 Stats 入口回到本页统计视图。

## 状态模型

```text
Hub
└── Backlog · PRD 已选中 · 「执行过程」标签
    ├── 顶部：当前阶段 / Agent 尝试 / 完整性
    ├── 四类耗时：端到端（主）= 有效执行 + 等待 + 阻塞（互斥）
    ├── 生命周期时间线（按发生时间升序）
    │   ├── 缺口披露区：不可用 / 无归属 / 截断各说一件事
    │   ├── 执行会话分组（事件 detail 里的 invocation_run）
    │   │   ├── 会话级事件行（同秒 started/claimed 折叠成一行 + 可点开的标记）
    │   │   └── Agent 尝试 #N（摘要：agent / 失败类别 / 耗时 / 是否恢复）
    │   │       └── 展开调用序列 → 每次进程调用一行（阶段 / 角色 / 执行器 / 终态 / 耗时 / 模型 / 重试链 / 日志）
    │   └── 无会话标识的事件：保持原顺序平铺 + 一行说明
    ├── 点击任一事件（含被折叠的）→ 事件详情抽屉（含原始 detail）→ 关闭
    ├── 场景切换：正常轨迹 ⇄ 失败与重试 ⇄ 观测写入失败 ⇄ 调用明细不可用 ⇄ 旧记录（无归属）
    └── 「查看统计」→ PRD 执行统计
        └── 点击当前 PRD 名称 → 返回 Backlog 生命周期详情
```

统计表的搜索框会按 PRD 名称、Issue 编号和状态筛选演示记录；统计周期固定为最近 30 天。只有当前 PRD 记录能返回对应生命周期详情，历史记录保持静态，避免误跳到当前 PRD。

## 关键点击语义

- 侧栏 **Backlog / Stats** 与详情页右上角 **查看统计**：在 Backlog 生命周期详情与仓库级统计之间切换。
- 时间线任一事件（点击或 `Enter` / `Space`）：打开事件详情抽屉；`×` 或 `Esc` 关闭。被折叠进同一行的事件（`+ 已被领取`、`+ 重试`）各自是独立按钮，照样能点开自己的原始 detail。
- 尝试行的 **展开调用序列（N 次）/ 收起调用序列**：button + `aria-expanded`，键盘 `Enter` 可达；展开状态跟随「会话 + 尝试」记忆，切换场景时重置。展开后没有调用时，说明原因而不是留白。
- **五个场景按钮**：切换五套稳定 fixture，同时刷新时间线、当前阶段与四类耗时。
- Stats 表格第一行 PRD 名称：返回其生命周期详情；其余归档 / 失败行为静态展示。
- Stats 顶部 `未关联 PRD` 提示与表格末行：演示旧记录降级，不提供生命周期链接。
- 底部原型 Dock（评审工具层，非产品 UI）：**可点击区域开关**（默认开启）、**↺ 重置**（回到初始场景与 Backlog 视图）、**返回 Hub**、**原型说明**。

## 五套演示场景

| 场景 | current_phase | 演示的产品语义 |
|---|---|---|
| 正常轨迹 | `reviewing` | 两个执行会话、每会话一次尝试；同秒 `started`/`claimed` 与 `retry`/`attempt` 各折叠成一行；观测事件走中性「观测记录」徽章；展开后可见正常退出、异常退出（带重试链）与**未闭合**（耗时不估算）三类调用行。 |
| 失败与重试 | `blocked` | 三次尝试跨两个会话，失败事件与各次耗时全部保留；调用账本达到读取上限 → 单独披露**已截断**，只显示读到的那部分。 |
| 观测写入失败 | `validating` | 一次事件写入失败，页面顶部显示**数据不完整**告警、完整性标为「数据不完整」；runner 主流程仍完成。 |
| 调用明细不可用 | `reviewing` | 调用账本读取失败：披露不可用、展开项说明原因，时间线其余分组与事件照常渲染（缺口不吞掉其他信息）。 |
| 旧记录（无归属） | `completed` | 事件里没有会话标识、响应里没有 `invocations` 区：回落单层平铺 + 两条披露，不按时间窗口虚构分组与调用序列。 |

## 口径与降级（原型要评审的核心结论）

- **端到端是主指标**：从首次进入执行队列到归档的完整历时，而不是一次 runner 调用的 `duration_seconds`。
- **执行 / 等待 / 阻塞互斥**：详情页固定展示三项拆分，并在下方用一行等式复算「端到端 = 有效执行 + 等待 + 阻塞」，强调前端只格式化、不重算。
- **进行中不伪造结束时间**：进行中的 run 端到端「计算到当前时刻」，状态显示「进行中」；阻塞中显示「阻塞中」与当前阶段。
- **失败不被覆盖**：失败事件与各次 attempt 耗时全部保留在时间线上，后续成功只追加、不重写历史。
- **分组只认显式字段**：会话归属取事件 `detail.invocation_run`，尝试归属取 `detail.attempt_number`；缺字段就进「未归属」平铺，绝不用时间窗口猜关联。
- **去噪只作用于展示层**：折叠的是行，不是事件——被折叠事件仍可单独点开，账本内容零改写、零删除。
- **纯观测事件不借阶段语义**：`agent_token_usage` 显示中性「观测记录」，不得回落成「未开始」这类与事实不符的徽章。
- **调用行的诚实字段**：未闭合调用的结束时间显示「未闭合」、耗时显示「未记录」；模型区分「KC 下发」「执行器报告」与「无法确认」三态，不互相冒充。
- **三类缺口分开说**：读不到（不可用）、没法归属（无归属旧数据）、只读到一部分（截断）各自成句，任何一类都不阻断其余渲染。
- **旧记录降级**：无法可靠归属 PRD 的记录标为「未关联 PRD」，在最近运行列表可见，但被排除出完成分位数统计。
- **旁路降级**：观测写入失败不阻断 runner，但页面必须明确显示数据不完整，而不是静默假装完整。

## 模拟范围

- 模拟 `RoadmapPrd`、生命周期 run/event、attempt、调用明细与仓库统计聚合后的**目标展示形态**。
- 所有数字、run id、会话标识、调用 ID 与文案均为**稳定 fixture**，不含随机数与定时器，也不暗示已存在生产 API。
- 调用行 fixture 的字段名逐条对齐后端 `PrdInvocationRow`；时间线词汇（阶段 / 事件类型 / 终态 / 模型三态 / 披露文案）与生产组件 `prd-lifecycle-timeline.tsx`、`prd-lifecycle-format.ts` 保持同源，改文案要两边一起改。
- 为可读性，事件与调用时间只写时:分:秒（省略日期）；生产展示完整本地时间。
- 统计搜索只过滤当前静态 fixture；未实现真实日志流、后端数据刷新、周期选择、分页、权限、错误请求与跨仓库切换。

## 设计依据

- 产品 shell、色彩与排版参考 `frontend-public/app/(app)/`、`frontend-public/app/globals.css` 与现有 Backlog / Stats 页面；原型完全由 HTML/CSS/JavaScript 构建。
- 生命周期详情沿用统一 PRD 详情的「PRD 原文 / 验收证据」标签结构（`frontend-public/components/roadmap/prd-detail.tsx`），新增「执行过程」。
- Stats 入口沿用 `frontend-public/app/(app)/app/stats/page.tsx`，把统计口径从单次 runner 记录改为完整 PRD 生命周期。
- 字段命名对齐后端只读契约：明细 `GET /v1/agent-runner/roadmap/prds/{encoded}/lifecycle`，统计 `GET /v1/agent-runner/console/stats/prd-lifecycle?repo_id=&days=`；`current_phase` 与 `event_type` 取值来自 PRD §7 的闭集。
- 本原型不使用 AI 生成图片，因此不需要 `.prompt.md`；代码与本说明即来源记录。

## 生产实现仍需确认

- 生命周期事件的持久化 schema、旧运行记录迁移与数据保留周期。
- 「执行时间 / 等待时间 / 阻塞时间」的精确定义与跨时区聚合，以及进行中 run 的「当前时刻」基准。
- Issue 与 PRD 路径无法关联时的降级标记规则，以及分位数排除口径。
- 观测写入失败的可诊断错误上下文（仅结构化摘要，不落敏感原始输出）。
