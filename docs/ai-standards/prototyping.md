# 原型与 UI 草图规范

本页是仓库内创建、评审和保存 UI 原型的项目规范。即使没有安装或调用相关 Skill，也按本页执行。它约束的是原型交付，不代表已实现生产功能。

## 开始前

1. 阅读仓库根目录的 AGENTS.md 和本页对应的项目标准。
2. 查看真实页面、路由、父级布局、现有组件、设计令牌和可复用原型；优先沿用已有页面结构和导航。
3. 检查目标文件的 git status，保留现有改动。先判断任务是视觉探索、交互流程验证还是生产界面实现，不把三者混为一谈。
4. 先写清要解决的问题、要保留的产品结构、需要评审的状态，以及原型尚未实现或验证的部分。

AI 生成的后台界面只提供视觉方案，不是产品事实。页面文案、导航、业务数据和交互语义应来自真实代码或用户确认；无法确认的内容标为示意，不据此声称生产行为。

## 选择原型形式

- **视觉概念图**：只比较版式、入口位置或视觉方向时，可用单张或多张静态图。说明它是概念图，不可点击，也不证明产品行为。
- **交互原型**：需要评审状态变化、表单、筛选、抽屉或导航时，使用项目现有前端栈和真实产品外壳，提供一个明确入口和可走通的状态流程。
- **混合原型**：复杂视觉由图片表达、关键操作由 HTML/CSS 控件实现时，明确图片和代码各自承担的部分。

用户明确要求图像生成模型，或主要目标是比较高保真视觉方向时，使用可用的图像生成工具；需要精确表达流程、结构或交互时，用项目代码或可编辑图表表达。

只做用户要求的最小原型。不要为了让图片看起来完整而虚构未确认的业务规则、数据或产品组件。

## 文件位置

- 修改已有原型时，扩展该原型的现有目录和资产位置，不另建重复页面或清单。
- 本仓库已有的页面式原型继续使用 docs/prototypes/原型名.html、对应说明文档，以及 docs/prototypes/assets/原型名/ 下的功能图片。
- 新建独立原型时，使用 docs/prototypes/feature-slug/，至少包含入口文件、assets/ 和 prototype.md。
- 共享的通用资源才放在 docs/prototypes/assets/ 根目录；具体功能图片放进对应原型的资产子目录。
- 新增或实质修改独立原型时更新 Prototype Hub registry。Hub registry 是原型入口和状态的唯一清单；docs/prototypes/index.md 只链接 Hub 和说明页，不再复制一份原型列表。

## 图片来源与旁车

图片放在对应原型的资产目录。每张正式保留的图片必须能追溯来源：

| 图片来源 | 配套记录 | 必须记录 |
|---|---|---|
| AI 生成或编辑 | 同名 .prompt.md | 完整提示词、参考图、保持不变的区域、本次变化、画布尺寸、工具和日期 |
| 浏览器截图或设计工具导出 | 同名 .source.md | 真实代码入口、页面与状态准备、采集工具、视口和日期、验证层级 |
| 手工绘制 | 同名 .source.md | 源文件或绘制方式、画布尺寸、用途和验证层级 |

用于继续编辑的参考图应保存在仓库内的稳定路径，旁车使用相对路径指向它们；不要只记录临时目录路径。浏览器截图不编造生成提示词，AI 生成图也不能伪称为真实产品截图。

一次探索有多个候选时，使用清楚的候选名称。用户选定后，将选中图和旁车放入原型资产目录，并按用户意图清理未选稿；不要把未选候选误登记成可用原型。

## 说明与验证

- 原型说明应写明目的、入口、状态或页面关系、图片与代码各自表达什么、示意数据、限制，以及与生产页面的关系。
- 只用于视觉决策的静态图标为“设计概念”或“视觉草图”；不称为交互原型、component preview 或 E2E 证据。
- 可点击原型从明确入口启动；实际点击主要控件，验证状态变化、返回路径和键盘操作，并在桌面与窄屏检查布局。记录验证层级；临时预览、直接渲染组件或手工注入状态不能称为真实生产入口验证。
- 只有真实生产路由和对应后端行为都经过验证，才能声称已完成生产功能验证。原型的视觉认可也不自动授权生产代码改动。

交付时给出所选原型的文件位置、形式、验证层级和未覆盖行为。不要仅交付孤立图片而遗漏来源记录。
