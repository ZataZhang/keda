# 本机文件与改动查看器

`just view` 起一个只绑本机回环地址的界面：默认落在**改动视图**——左边按「Staged Changes /
Changes」两段列出有改动的文件，右边是逐行 diff，顶部可以一键切到文件树视图。它代替「为了读
一个文件或看一眼 diff 就开一个完整 IDE」这件事。文件视图里 Markdown 默认按渲染结果打开、图片
直接显示、HTML 可以在新标签页里当真实文档打开，边界见下文「预览的边界」一节。

**查看器不编辑仓库；它可以暂存改动，也可以把文件交给系统默认应用打开。** `Changes` 里的加号
（`git add`）是唯一会改变仓库的动作——没有编辑、没有提交、没有丢弃改动，也没有「取消暂存」。
内容区头部的「在系统中打开」会调用 macOS `open`、Windows 文件关联打开器或 Linux `xdg-open`，
不写仓库，但会在本机拉起应用。两条操作都只接受 JSON 请求体（跨站表单式 POST 会被浏览器直接发出，
JSON 类型则强制预检、预检必然失败），于是「某个网页在你不知情时改动索引或拉起应用」这条路被封住。
需要改代码、或者需要提交与撤销，请用你惯用的工具。

## 命令面

| 命令 | 作用 |
|---|---|
| `just view` | 起（或复用）本仓库的查看器，并在浏览器里打开，默认进改动视图 |
| `just view <路径>` | 打开后直达某个改动文件；路径是相对仓库的路径 |
| `just view --files` | 进文件视图而不是改动视图，显示完整文件树 |
| `just view --diff` | 显式进改动视图（与 `just view` 等价，保留为显式写法） |
| `just diff` | `just view --diff` 的薄别名，无独立实现 |
| `just view --stop` | 立刻回收本仓库的常驻实例 |
| `just view --port <端口>` | 指定监听端口（优先级：显式 `--port` → 登记里的值 → 默认 8791 → 系统空闲端口） |
| `just view --idle-timeout <秒>` | 空闲回收时限，`0` 表示关闭自动回收 |
| `just view --no-reuse` | 强制新起一个实例，不复用既有实例。旧实例不会自动收掉，需要时用 `just view --stop`，或等它自己闲置回收 |
| `just view --no-open` | 只打印 URL，不打开浏览器 |

`--diff` 与 `--files` 互斥。改动视图是默认视图，因此 `just view --diff` 与 `just view`
等价；`--files` 是回到文件树的唯一入口。

改动视图永远两段全列，没有「只看某一段」的开关，也没有比较基线可选：比较对象固定是当前
工作区，用 `git status` 的口径切开再合并成两段（见「界面用法」里对两段的说明）。

每个 worktree 各自独立：登记文件与端口按 worktree 分开，多个 worktree 或派生项目并存
时互不干扰。派生项目 `just sync-template` 之后同样获得这条命令，不需要本地分叉。

## 界面用法

- **改动视图**（默认）：左树分两段——**`Staged Changes` 与 `Changes`**（与 VSCode 对齐；
  `Changes` 是「未暂存」与「未跟踪」合并显示的结果）——每段一条标题行（带该段文件数），段内再
  按目录分组。折叠有三层粒度：**点分段标题收起整段**（整段的默认值两段不同：`Staged Changes`
  默认**收起**——那是已经看过、等提交的部分；`Changes` 默认**展开**——那才是手头正在改的）
  → 段内目录（默认**展开**，这里只有改动涉及的目录，本来就没几个）→ 叶子行；目录行折叠后显示
  其下的改动文件数。目录折叠与分段折叠都**每段各自记**（同一个目录路径可能出现在两段里，折了
  一段里的 `previews/` 不会连带折起另一段的），且都只在**本次会话内**记住——刷新按钮与暂存后
  重新取列表都保持，浏览器刷新页面才回到默认的展开/收起；过滤框里有词时一律强制展开（命中项被
  藏在折叠的分段或目录里，界面和「没有命中」长得一模一样）。叶子行显示状态徽标与 `+N -M`；
  文件名按所属分段着色——`Changes` 段呈淡绿、`Staged Changes` 段保持默认色，同一个文件同时
  出现在两段里时一眼可分；层级由缩进参考线表达（每层祖先一条淡竖线，目录名加粗一档），两个
  视图共用。点开任一文件看逐行 diff（旧行号与新行号并列，增行绿底、删行红底）。二进制文件没有
  逐行内容，其中**图片**会给出旧新两版对比（见下文「预览的边界」）。两个视图共用同一套目录树，
  只是叶子行不同。
- **把改动加进索引**：`Changes` 的**标题旁**有一个加号（全部暂存，等价 `git add -A`），每个
  **文件旁**也有一个（只暂存它，等价 `git add -- <路径>`）。暂存之后那个文件就出现在
  `Staged Changes` 里；若它当时正被选中，选中项会跟过去，不会留下一句「该区段下没有改动」。
  这是界面唯一会改变仓库的操作。被忽略的文件不会被 `-A` 带进来（那是「这不是源码」的权威信号）。
- **没有「取消暂存」**：`Staged Changes` 上没有反向的减号。这是**刻意不做**，不是漏了——用户
  的判断是那样用的频率低，真要撤销暂存就用惯用的 git 工具（`git restore --staged <路径>`）。
  什么时候想加回来，改这一处即可；这个决策连同理由记在 `tasks/inbox/ideas.md` 与提交信息里。
- **统计列**：正常文件给 `+N -M`；二进制文件给一个 `01` 徽标（这一列只有十几像素宽，三个
  汉字会折成三行把行高顶开，`01` 与同排的 `A` / `D` / `R` 一样是语言无关的短记号，含义靠
  悬停说明与提示块正文兜住）；未跟踪文件整列留空（见下条）。
- **服务端仍按三段取数，合并只发生在显示层**：已暂存取 `git diff --cached`（HEAD ↔ 索引），
  未暂存取 `git diff`（索引 ↔ 工作区），未跟踪取 `git ls-files --others --exclude-standard`
  列文件，点开某个文件时才用 `git diff --no-index -- /dev/null <文件>` 求它的逐行 diff。
  三段的 git 口径互不相同，单文件 diff 与暂存动作都要知道自己面对哪一种，所以不能在服务端
  合并计算。界面上的文件集合与增删统计与这些命令的终端输出逐项一致，不做二次推断。
- **未跟踪文件不显示 `+N -M`，因此 `Changes` 标题上只给文件数**：`git` 的列表类命令都不为
  未跟踪文件报这个数，唯一能拿到它的口径是逐个文件跑一次 `--no-index --numstat`。本机实测每个
  文件约 8ms，800 个未跟踪文件要 7 秒左右（并发跑到 8 路也只降到 4 秒，瓶颈在进程创建），页面
  会像卡死。因此这些条目只列文件、统计列留空——**不编数字**，也不把「本轮没取」显示成 `01`
  （二进制那个徽标）。合并之后 `Changes` 里混着未跟踪文件，只把其中一部分加起来当成整段合计同样
  是编数字，所以那一段的标题只报文件数，逐文件的增删照旧各自显示。
- **同一个文件可以同时出现在两段里**：暂存之后又改的那几行属于未暂存。条目的身份因此是
  「路径 + 底层分区」，两段各自的 diff 内容不同。`just view <路径>` 直达时按分区顺序（已暂存
  优先）取第一个匹配的段落。
- **未跟踪那部分沿用文件树的目录剪枝**：派生项目忘了把依赖目录写进 `.gitignore` 时，整棵
  依赖树既不该进文件树，也不该淹没改动列表。两处是同一份口径。
- **文件视图**：点顶部「文件」切过去，左侧是完整文件树，点文件在右侧看带行号与语法高亮的
  正文。**目录默认折叠**——仓库动辄几百上千个文件，全摊开是一堵墙；点目录行展开，再点收起。
  树头的「忽略项」开关可按需显示被 Git 忽略的文件，默认关闭；这些行带「忽略」标记，只能只读查看，
  不会出现在改动视图或暂存操作中。依赖与缓存目录（如 `node_modules/`、`.venv/`）仍按目录剪枝隐藏，
  避免一次展开大量文件。
  手工折过或展过的目录会被记住，切来切去不会自己弹回去（折叠状态按树记：文件树与改动视图的
  每一段各记各的，互不牵连）。顶部过滤框按路径筛选（两个视图都适用），命中的路径其祖先目录
  会自动展开（**包括**被手工折起来的那些——过滤出一个「有命中却全是折叠目录」的空树，和
  「没有命中」在界面上长得一模一样，是明确错误的结论）。
- **左栏可以加宽**：文件树标题右侧有一个小图标按钮（双箭头，常态指向右），点一下把左栏放宽到
  **放得下最长的那一行**（下限 340px、上限视口的 60%——长路径撑得开左栏，内容区却不会被挤没），
  箭头随之翻向左边（按钮同时带一层淡底，表示「现在就是加宽态」），再点一下回到原来的窄栏。它只
  改布局、不发任何请求；与目录折叠一样只在**本次会话内**记住（刷新按钮与切视图都保持，浏览器刷新
  页面回到窄栏）。窄窗口下（视口 ≤ 860px，左树本来就占满整屏宽、文件名放得下）这个按钮不显示。
- **预览**：默认按文件类型定。打开 `.md` **直接进预览**（文档先看渲染结果），头部有「源码 /
  预览」开关可以切回源码，渲染结果取回后缓存在内存里，来回切换不再重复请求；其它文本文件默认
  源码。打开 `.html` 时头部给的是「在新标签页打开」——查看器不内联渲染 HTML，而是把文件原样
  供出，让浏览器在自己的标签页里当一个真实文档打开，页面里的相对引用（`./a.css`、
  `../img/i.png`）能按原路径解析回来。打开 `.png` / `.jpg` / `.gif` / `.webp` / `.ico` 直接
  显示图片，没有源码可切，所以头部不摆开关。控件都只在当前文件支持时出现；有真实文件路径时，
  头部还提供「复制路径」与「在系统中打开」。二进制和大文件无法在查看器里渲染时，头部仍保留这两个
  按钮，方便复制路径或交给本机应用。
- **放大图片**：内容区里的图片都能点——文件视图的图片预览、改动视图里旧新两版的任一张、以及
  Markdown 里引到的图。点一下先按「适应屏幕」铺满整屏看全貌，**再点图片本身**切到「原始像素」
  （不缩放、整层可滚动，截图里的字才真的看得清），点图片可在两档之间来回切。点空白处或按 `Esc`
  关掉；放大层开着时 `f` / `d` / `/` 不生效，免得看大图时把视图换掉。
- **重命名**：状态徽标为 `R`（蓝色），点开后按「旧路径 → 新路径」配对给出逐行改动。
  内容没变的纯重命名会明说「重命名，内容未变」——路径确实变了，不能报成「没有改动」；
  内容也改了的，头部会标注重命名自何处并照常给 hunk。
  用普通 `mv` 搬文件（不是 `git mv`）同样只占一条：原位置的删除与新位置的未跟踪文件会合成
  一条 `R`，统计列给出真实增删、点开只显示改动的那几行。这类配对在仓库之外的一次性索引上完成，
  你的索引一个字节都不会被改到。唯一例外是配不上对的候选：一个删除同时有好几个相似的新文件时，
  只有最像的那一个成为 `R`，其余照旧是 `A` 且不带统计。
- **二进制与超大文件**：超过 256 KiB 的文件与二进制文件给出明确说明而不是渲染正文（图片是
  例外，见下文「预览的边界」）。
  改动视图里二进制的改动会被标成 `01`（统计列）与「二进制文件，无逐行改动」（提示块）——
  它确实变了，只是 git 不逐行给，不能报成「没有改动」。
- **复制路径**：内容区头部路径右侧有一个复制按钮，点一下把该文件的仓库相对路径写进
  系统剪贴板，图标短暂变为对勾作为反馈。头部没有真实路径时（未选中文件、提示块、服务
  已退出）按钮自动收起。
- **两个视图各记一份「上一次看的那一个」**：在改动里看到一半切去翻文件、再切回来，仍停在
  原来那条改动上（分区一起还原，同一个文件的两段不会串）；反过来也一样。只有**成功读到内容**
  才被记住，读失败的提示块不会占住这个位置，否则每次切回来都会重弹同一个错误。还原是尽力
  而为：文件被删了就照实说「未找到文件」，改动被提交了就让改动视图回到空态。
- **从改动跳到文件**：改动视图里选中任一改动文件后，头部路径右侧出现「查看文件」，点一下切到
  文件视图并选中同一路径的完整正文（祖先目录会自动展开，选中态在树上可见）。这一步是显式指定，
  **优先于**上面那条记忆——它要的是「看你点的这一条改动对应的文件」，不是「回到上次看的文件」。
  文件视图里不显示这个按钮——那里本来就在看正文。改动里已被删除的文件跳到文件视图会得到明确的
  「未找到文件」：文件确实不在了，查看器不拿索引里的旧内容冒充它。
- **刷新**：顶部右侧的「刷新」重新读取仓库信息、**文件树**与当前视图的内容（改动视图重新列
  改动，文件视图重读当前那个文件；文件已被删就照实报「未找到」）。**页面不会自动刷新**——它
  刻意不做任何轮询，原因见下文「常驻与回收」；需要最新状态时按一下这个按钮（浏览器自带的刷新
  当然也可以）。文件树只在打开页面时取过一次，所以**新建或删除的文件必须刷新过才会出现**。
- **「距上次刷新」的正计时**：刷新按钮右边那个 `分:秒` 是距上次刷新的时长，打开页面时从零起算、
  点「刷新」归零、服务退出后收起。它只是把「你看到的这份状态有多旧」摆在眼前——查看器不会自己
  跟上文件变更，而人很容易以为它是实时的。这个数字**纯本地计时，不发任何请求**（「不轮询」那条
  口径说的是请求），暂停一会儿不看它也不会让服务端少回收一秒。
- 快捷键：`d` 切改动视图、`f` 切文件视图、`/` 聚焦过滤框。

## 预览的边界

预览的**默认值按文件类型定**，判定**只看后缀，不做内容嗅探**——与语法高亮同一口径：让
「这个文件预览成什么」随正文漂移，排障时无从解释。

| 文件 | 打开时默认 | 头部给的入口 | 走哪条路 |
|---|---|---|---|
| `.md` / `.markdown` | 预览 | 「源码 / 预览」开关 | 服务端渲染成 HTML 片段，取回后内联进内容区；片段里的相对引用已改写成能取到字节的地址；其中的 mermaid 围栏由页面里的 mermaid.js 画成图 |
| `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.ico` | 图片 | 无（没有源码可切） | 内容区放一张指向 `/raw/` 的 `<img>`，字节由浏览器自己取 |
| `.html` / `.htm` | 源码 | 「在新标签页打开」 | 文件字节原样供出，由浏览器在新标签页里渲染 |
| 其他文本文件 | 源码 | 无 | — |

几条明确的边界：

- **改动视图里的图片改动做旧新对比**：git 对二进制不给逐行内容，但图片的画面本身可比，所以
  那里不再只有一句「无逐行改动」，而是并排给出两版——`Staged Changes` 里比 HEAD ↔ 索引；
  `Changes` 里的未暂存文件比索引 ↔ 工作区，未跟踪文件只有工作区那一版（它还没有进过索引）。**宽屏左右并排，竖屏或窗口
  窄到放不下两栏时改成上下**（断点：`orientation: portrait` 或视口宽度 ≤ 1100px）。只取得到
  一版时就只画一版，并用一句话说明另一版为什么不在（新增 / 删除 / 未跟踪）。重命名且改了内容
  的图片，旧侧按**旧路径**取，标签里也写出旧路径。普通 `mv` 搬过来的图片是这里的一个例外：它
  在未跟踪那一段，旧侧照旧不取，因此只画一版并说明另一版不在——行本身仍是一条 `R`。
- **历史版本的字节走 `/raw/<路径>?rev=head|index`**（工作区那版不加 `rev`，与其它地方一致）。
  取值是封闭枚举，未列出的取值 400；路径照旧经过与其它读取接口同一份越界断言。
- **非图片的二进制不给对比**：压缩包、可执行文件没有可比的画面，照旧只说「无逐行改动」。
- **改动视图不预览**：那里对 `.md` / `.html` 仍是逐行 diff，头部也不会留下预览控件——从文件
  视图带着一个 `.md` 切过来时，「源码 / 预览」开关与「在新标签页打开」都随正文一起收掉。图片
  走的是上面那条旧新对比，同样不是预览控件。
- **渲染依赖缺失时 Markdown 预览入口不出现**，源码与语法高亮照旧。`markdown` 与 `pygments`
  一样是显式声明的 dev 依赖；派生项目 `uv sync --no-dev` 之后查看器功能不缺失，只是 Markdown
  默认回到源码视图。
- **256 KiB 上限只约束文本**：超过它的 Markdown 与其它文本走大文件分支，不预览也不高亮。**图片
  不受这条约束**——它的字节是浏览器直接向 `/raw/` 取的，服务端一次都不读，没有可省的开销；
  截图动辄超过 256 KiB，把上限套上去会把最该能预览的那一类文件挡在门外。
- **`.svg` 不按图片预览**，仍按文本给它语法高亮：SVG 是可编辑的源码，源码视图对它更有用。
- **mermaid 图由浏览器画**：正文里 ` ```mermaid ` 围栏由服务端换成 `<pre class="mermaid">`（只认
  信息串恰好是 `mermaid` 的围栏），图本身交给页面里的 mermaid.js 读那个块的文本去画，画完把内容
  换成 SVG。服务端不认识 mermaid，**语法不校验**——写错了由 mermaid 在块里画一段错误说明，状态条
  也会写一句；页面拿不到那份资源时块里留着的就是围栏源码（按等宽字体显示），降级方向与其它
  依赖缺失一致。那份 mermaid 是随查看器一起分发的第三方产物 `assets/mermaid.min.js`：官方压缩包
  v11.17.2（MIT，取自 `https://cdn.jsdelivr.net/npm/mermaid@11.17.2/dist/mermaid.min.js`，
  sha256 `581ed7d74bd9048d0e3a91363927d72ef22942d7722546b27f7cc29e35390eb8`，与上游逐字节一致
  ——pre-commit 的文件卫生钩子对它是放行的）。它**按需取**：预览里真出现 mermaid 块时页面才插一次
  `<script>`，3.5 MB 不进首屏。升级就是换掉这个文件、更新这几行说明与 `viewer.js` 里的版本号，
  然后在真浏览器里把图看一遍。
- **Markdown 里的 raw HTML 会被执行**，但正文里的相对引用（markdown 语法的图片与链接、以及
  手写的 `<img src="…">` / `<a href="…">`）会被**改写**成能真正取到字节的地址：预览片段是内联
  进查看器页面（`/`）的，不改写的话相对引用照着页面根解析必然落空——图片就是这么变成一片空白
  的。`src` 一律指向 `/raw/<仓库相对路径>`；只认后缀判定，`.md` / `.markdown` 的链接改走查看器
  直达链接（`/?view=files&path=…`，点一下就在查看器里读它，而不是一屏原始 markdown 文本），
  其余链接照旧指向 `/raw/`；前导 `/` 按**仓库根**相对解释（否则 `/assets/x.png` 会撞上查看器
  自己的静态资源目录）。以下四种**原样保留**，因为猜错比不改更糟：带 scheme 的
  （`https:` / `data:` / `mailto:` …）、协议相对的（`//host/…`）、纯片段的（`#锚点`）、带查询串
  的（`/raw/` 的 `?rev=` 与直达链接的 `?path=` 语义完全不同，接在任一种地址后面都换个意思），
  以及解析之后跑出仓库根的（`../../x`）。`srcset` / `poster` 这类属性不处理。
  查看器绑在本机回环上，只有读取、暂存与用户点击后在系统中打开三种能力；预览又是用户主动点开的一次；这里刻意不做清洗
  ——清洗过的结果已经不是文件本身，那比不预览更容易误导。
- **HTML 走原样供出的路由**（`/raw/<仓库相对路径>`），并且保持路径原样，这是相对引用能
  生效的前提。它仍然逐字经过与其它读取接口同一份越界断言（解析成绝对路径后必须仍在仓库
  根之下），目录、缺失与越界分别给出明确拒绝。图片预览用的是同一条路由。
- **在新标签页里打开的页面与查看器同源**：那个静态文件里的脚本因此可以调用查看器的接口——
  包括暂存与在系统中打开（同源请求不需要预检，JSON 要求拦的是跨站）。查看器只绑回环，被打开的又本来
  就是仓库里的文件，这一点按接受处理而不是靠沙箱隔离——真要隔离，代价是相对资源全部加载不到。

## 与 `git status` 的差异

改动视图按需向 `git` 取数据，不调用 `git status`，因此有两点值得知道：

- **未跟踪**那些文件的集合来自 `git ls-files --others --exclude-standard`，与 `git status`
  里 ``??`` 的口径一致；但被上述目录剪枝挡掉的路径不会出现。
- **被忽略的文件**（``!!``）默认不出现在文件树或改动视图。文件视图打开「忽略项」后，
  `/api/tree?include_ignored=1` 会列出被忽略的普通文件；依赖与缓存目录仍被剪枝。忽略项不会进入
  改动视图，也不会被「全部暂存」带进索引。

## 常驻与回收

查看器是一个常驻本机进程，「第二次打开是秒开」正是它换来的：命中的第二次调用只开一个
新标签页，不重启进程。

常驻进程必须同时具备两条回收路径，这是本仓库不接受「常驻但没人管」的直接结果——见
`docs/ai-standards/tooling.md` 里那条「手敲的三次 `just test` 在 14 小时后仍常驻内存」
的教训。

- **自动回收**：服务按「最后一次请求时间」计时，默认 **30 分钟**没有任何请求就退出并
  清理登记。时限可用 `--idle-timeout` 调整，`0` 表示关闭自动回收。
- **显式回收**：`just view --stop` 读登记 → 给服务进程发终止信号 → 清理登记。结束实例
  刻意走进程信号而不是 HTTP 接口：那个写口是给用户的**暂存**动作（`POST /api/stage`），
  不是运维通道——不为运维便利再开第二个口子。

**页面不做心跳轮询**，所以「关掉标签页」就等于进入空闲，关掉后不必再管它。代价是页面
开着但长时间不碰也会被回收，此后页面会失效。服务退出后页面会切换到明确的「服务已退出」
提示并给出重新连接指引，而不是留一个半渲染的坏页面——重新执行 `just view` 即可。

要看最新状态就点顶部的**刷新**：它是用户按下来才发的那一次请求，因此上面这条口径不变
（页面自身仍然不会周期性地产生任何流量，也就不会把回收挡住）。刷新按钮旁那个正计时也只改
本地文字，不发请求。

## 性能承诺边界

承诺只覆盖**进程侧**，而且只承诺这两条：

| 路径 | 承诺 |
|---|---|
| 复用命中（第二次及以后的 `just view`） | 从敲命令到浏览器开始加载 ≤ 150ms |
| 冷启动（首次 `just view`） | 从敲命令到首个只读接口返回成功 ≤ 400ms |

**这两条余量对机器负载很敏感**：路径上只有一个 `just` 进程加一个 Python 解释器，两者
的成本几乎全是解释器启动与导入，而这部分在 CPU 被别的进程挤占时会被放大约一个数量级
（本机实测空载 `python -c pass` 约 9ms，负载 17 时约 50–100ms）。同一份代码在空载机器上
两条预算都有十倍余量，在超载机器上则可能双双超标。想判定它是否达标，请在机器不忙时
测，并在记录里带上当时的 load average——`rv5_measure.py` 会把它打在证据首行。

**浏览器冷启动不在承诺内**：本机实测浏览器未运行时冷启动要 1.5–3s。这是环境成本而不是
实现缺陷——查看器能把进程侧压到预算内，但没法让一个还没启动的浏览器提前加载。首次使用
时请把这 1.5–3s 算进去。

## 实例登记与排障

常驻实例登记在仓库根的 `.env.view-state`，与既有的 `.env.run-state` 同构：被 `.gitignore`
的 `.env*` 规则覆盖、不进版本库、每个 worktree 各自独立。

| 字段 | 含义 |
|---|---|
| `VIEW_PID` | 服务进程号，`--stop` 据此投递终止信号 |
| `VIEW_PORT` | 服务监听的本机回环端口 |
| `VIEW_REPO_ROOT` | 实例所服务的仓库根绝对路径，用于判定登记是否属于当前仓库 |
| `VIEW_STARTED_AT` | 启动时刻，仅供排障阅读 |

复用判定做三项交叉校验：**进程存活 + 端口可连 + 仓库路径一致**。三项缺一不可——单看
进程存活会撞上进程号复用，单看端口可连会撞上端口被别的进程占用，仓库一致这一项则让同一
台机器上的多个项目互不串台。任一校验失败即判定登记陈旧，清理后重新起服务，而不是打开
一个连不通的页面。

排障入口有三处：

1. `.env.view-state`：判断登记项是否陈旧、实例占的是哪个端口。
2. `logs/view-viewer.log`：服务的启动与回收日志（`logs/` 被 gitignore 覆盖）。
3. `just view --stop`：显式回收；登记项已陈旧时它只清理登记。

典型症状与处置：

| 症状 | 先查什么 |
|---|---|
| `just view` 每次都在重新起服务 | 登记文件是否被反复清掉；`logs/view-viewer.log` 里是否有空闲回收记录 |
| 页面提示「服务已退出」 | 正常回收路径。重新执行 `just view` 即可；想常驻不回收就 `--idle-timeout 0` |
| 端口被占用导致退让到随机端口 | 端口实际值只写在 `.env.view-state` 里，不在任何文档里硬编码，以登记为准 |

## 语法高亮的降级

高亮由 Pygments 在服务端渲染，`pygments` 在 `pyproject.toml` 的 dev 依赖组里显式声明。
依赖缺失时（例如派生项目做了 `uv sync --no-dev`）服务不会崩，只是降级为纯文本——行号、
文件树与改动视图都照常工作，功能不缺失，只是没有颜色。状态条会写明当前是哪种。

## 与改动报告技能的分工

`skills/git-diff-report/` 产出的是**可发送、可归档的单文件静态 HTML 报告**；查看器产出的
是**本机实时界面**（不编辑仓库，可暂存改动或把文件交给系统默认应用打开）。两者读者与生命周期不同：查看器不依赖、
也不复制该技能的产物，报告
生成能力也不会被搬进查看器。

两个工具的**范围词汇**是对齐的，切换时不会看到两套口径：报告技能的 `staged` / `unstaged`
即查看器的 `Staged Changes` / `Changes` 两段。差异在于报告技能还支持 `range --base <基线>`（整条
分支相对某条基线的改动）与 `head`（暂存 + 未暂存合并），而查看器只看当前工作区——要
「提交与提交之间比了什么」请用报告技能或 `git diff <基线>...HEAD`。
