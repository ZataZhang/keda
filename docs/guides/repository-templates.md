# 目标仓库的 Issue 与 PR 模板

Keda 在 AI 内容生成阶段自动读取当前目标仓库本地检出目录中的模板，不需要新增配置。
适用于从 PRD 创建 Issue、从一句话需求创建 Issue，以及普通 Draft PR 的正文生成。
PR 发布使用对应 worktree 中的模板。

## 支持范围

在 `.github/`、仓库根目录和 `docs/` 下发现 `ISSUE_TEMPLATE`、
`PULL_REQUEST_TEMPLATE` 单文件及同名目录中的模板（名称大小写兼容）。
支持 Markdown 和 YAML Issue Forms，忽略 `config.yml` / `config.yaml`。
Issue Forms 作为参考交给 Agent，以字段名称和说明组织 Markdown 正文，不提交 YAML 表单。
不会自动应用模板 metadata 中的 labels、assignees 等设置，路由仍由 Keda 的现有配置决定。

Agent 根据任务选择合适的模板，保留相关栏目与清单；信息不足时标记待补充，不能编造或
勾选未经验证的项目。选择不明确时在正文中注明选择及歧义，供人工审阅。
PRD 路径、Issue 关闭引用和 Keda 验证标记仍遵循原有契约；普通 Issue 不得凭模板生成虚构 PRD 引用。

## 正文更新与限制

普通发布发现已有开放 PR 时直接复用，不会用新生成正文覆盖原有模板内容。
验证清单签核、验证结果和失败交接使用现有正文做局部更新，保留其他栏目。
Agent 获得的模板指令也要求更新时保留原有栏目和人工内容。

模板遵循是 Agent 指令，不是逐字段硬校验。关闭 AI 内容生成、使用确定性模板模式或
Agent 失败回退时，继续使用原有 Keda 正文，不保证套用仓库模板。
聚合 PR 使用独立的确定性验收契约，本次不适配；不会自动拉取组织级 `.github` 仓库默认模板，
也不会为读取模板执行 fetch。需要先让模板存在于目标仓库本地检出版本。

模板正文总读取预算为 12,000 字符；超出剩余预算的文件会在上下文及日志中标记省略，
不可读文件会记录警告。指向仓库外的符号链接不会读取。模板只是参考内容，不能覆盖任务指令或输出协议。

## 验证边界

集成测试调用三条内容生成用例，使用真实临时仓库文件和替身生成器验证模板上下文传递、
返回正文及既有锚点契约；不访问 GitHub，也不证明某个外部模型逐项遵循模板。
