## 第 1 项 · 确认答案隔离边界

**你在决定什么：** 是否接受 Agent 在一个只含基线文件和单次提交的新仓库里工作，运行后才放入评分测试，并在判分前还原依赖清单。若判错，Agent 可能从本机 Git 历史或测试里看到答案，评测结果就不可信。

> 是否同意“新建单提交仓库 + 判分材料延后放入 + 判分前还原依赖清单”，并接受“公开仓库的网络泄漏与模型记忆无法消除，只披露不假装解决”？（PRD §2 决策一）

白话说明：“单提交仓库”是从指定基线文件重新建立、只有一次基线提交的隔离副本；它不含主仓库后续 Git 历史。“判分材料”是用于检查修复是否正确的测试文件，它要等 Agent 结束后才出现。公开仓库仍可能被 Agent 联网访问，模型也可能记得旧修复，因此留出集只能衡量相对变化。

**已执行证据：** [rv-1-isolation-restore.txt](rv-1-isolation-restore.txt) 记录共享仓库负控可见多个提交、修复对象、评分测试和答案文件；真实 API 候选只看到 `commit_count: 1`，且上述对象/文件均不存在。探针改写测试和 `pyproject.toml`、`uv.lock` 后，判分结果为 `1 passed`。

**回复格式：** 回复“决策一同意”，或写出你希望改变的隔离边界及理由。

**你在决定什么：** 是否接受 v15→v16 只增加重复序号、重复次数和每题冻结基线三项数据，并重建结果表唯一约束。若判错，迁移可能无法保留旧记录，或限制以后为同一题保存多次执行结果。

> 是否同意只做这三处增量改动，并接受“结果表的唯一约束重建后不再原样回退”？（PRD §2 决策二）
